# Ordo 产品与功能

> 本文描述 Ordo **当前的**用户可见行为。实现位置与分层见 [ARCHITECTURE.md](./ARCHITECTURE.md)，字段与存储见 [DATA.md](./DATA.md)，编号含义见 [DECISIONS.md](./DECISIONS.md)。

## 1. 定位

| 项目 | 内容 |
| --- | --- |
| 一句话 | 一个现代、流畅、轻量的本地任务 + 项目桌面管理器 |
| 核心流程 | 快速捕获 → 清晰组织 → 直观看进度 |
| 目标用户 | 需要统一管理个人待办与多项目的知识工作者、开发者、学生；偏好离线、数据自持、轻量快速 |
| 边界 | 单用户、local-first、离线可用；无常驻服务、无网络依赖 |

**价值主张**：全程离线、响应快、体积小。数据自持（全部落在本机 SQLite），v1 提供手动导出/导入备份；云同步为未来扩展。

## 2. 任务

任务是最小管理单元。**子任务不是另一种实体**——它就是一条带父任务的任务行。

### 2.1 任务字段

| 字段 | 说明 | 必填 |
| --- | --- | --- |
| 标题 | 任务名 | 是 |
| 备注 | 纯文本描述 | 否 |
| 优先级 | 高 / 中 / 低 / 无（默认无） | 否 |
| 标签 | 多标签，多对多 | 否 |
| 截止时间 | 到分钟的时刻 | 否 |
| 复杂度 | 1–5 的难度估计，未评估时为空 | 否 |
| 所属项目 | 为空即「收件箱」任务 | 否 |
| 父任务 | 非空即子任务，层级只有一层 | 否 |
| 状态 | 待办 / 已完成（由 `completed_at` 与看板列共同表达） | 是 |
| 完成时间 | 完成时自动记录 | 自动 |
| 重复规则 | 每日 / 每周 / 每月 / 自定义间隔，可暂停 | 否 |

任务没有颜色字段；任务行上展示的是优先级与状态徽标。

### 2.2 子任务与层级

- 子任务通过父任务建立，**层级只有一层**：子任务下不能再挂子任务，已经有子任务的任务也不能再变成别人的子任务。校验在服务层，越层与自引用都被拒绝。
- 子任务是一条普通任务行，拥有自己的标签、评论、时间记录、依赖边与详情弹窗。新建时它跟随父任务的项目，不能跨项目；子任务不上看板、默认不重复。
- 父任务行可展开/收起，折叠时显示子任务完成进度（`已完成/总数`）；**完成父任务不会**自动完成其子任务。
- 软删除父任务时子任务一并离开（同一事务级联），恢复父任务时一起回来。

### 2.3 任务视图与呈现规则

四个任务视图：

| 视图 | 内容 |
| --- | --- |
| 收件箱 | 未完成且没有项目的任务 |
| 今天 | 未完成且截止时间落在今天结束之前——**已逾期的一并算在内** |
| 即将到来 | 未完成、截止在今天结束之后且在 N 天之内（N 可选 7 / 14 / 30，默认 7） |
| 已完成 | 所有带完成时间的任务（软删除的已完成任务可恢复） |

**子任务凭自己的截止时间/完成时间进入视图**，呈现规则（文档中称「规则 A」）：

- 父任务也在同一视图结果里时，子任务渲染在父任务行之下（自动展开，不重复成行）。
- 父任务不在结果里时，子任务自己占一行并带「父任务 · X」前缀，点该前缀跳到父任务。
- 筛选与排序只作用于**独立成行**的任务：挂在父任务下面的子任务是父任务的上下文，不参与优先级/标签筛选；独立成行的子任务照常参与。
- 工具条的「n 个任务」数的是视图列出的行（顶层行 + 独立成行的子任务），展开一个父任务不会改变这个数字。

**任务行是两行**（父任务行与子任务行同一套排版，行高 72px）：

- 第一行：展开箭头、勾选框、标题，行尾是计时按钮与「⋯」操作菜单。
- 第二行：标题下方的一排属性徽标——优先级、截止时间、标签、子任务进度、重复、阻塞中；子任务行放优先级、截止时间、阻塞中。徽标贴齐标题左缘，因此它读起来是标题的副行，而不是另一列。

### 2.4 重复任务

- 支持每天 / 每周 / 每月 / 自定义间隔（`interval ≥ 1`）的重复规则，可暂停、可取消。
- 完成时按规则生成下一次实例：`due_at` 从原截止时间推进一个周期；**补完成（该周期已经过去）时继续推进到第一个落在未来的周期点**，所以补完成不会再生出一个已逾期的实例（QA-13）。按月加法钳制到月末，且锚点逐周期推进（1 月 31 日 → 2 月 28 日 → 3 月 28 日）。新实例继承标题/备注/优先级/项目/标签/子任务与规则本身，追加回原列（看板路径回到来源列）。
- 子任务照抄描述/优先级/复杂度并重置为未完成，其截止时间随父任务推进**同样个数**的周期，从而保持与父任务的偏移。依赖边**不**继承（它们指向上一实例的行）。
- 暂停的规则、无截止时间的重复任务完成后都不生成下一次；已逾期的提前提醒不补发。

### 2.5 截止与提醒

- 截止日期精确到分钟，存 UTC；「今天/即将到来」的本地日期边界由前端按用户时区计算。
- 后台线程每 30 秒扫描一次，对未完成、未软删、有截止时间的任务，在**提前 1 小时 / 提前 10 分钟 / 到期时刻**各触发一次提醒；标记持久化，跨扫描与重启不重复。
- **子任务按自己的截止时间独立提醒**：父任务完成不再静默子任务；父任务被软删时子任务随级联一起离开提醒候选。
- 每次触发同时做两件事：应用内 toast 事件 + 系统桌面通知（由 Rust 直接发送，不经 webview，因此后台/托盘状态下一样可达）。
- 停机补扫：只补发到期提醒；截止已超过 24 小时的陈年逾期不再提醒。
- 点击定位：插件桌面端不暴露通知点击回调，点击系统通知由 OS 聚焦应用窗口；窗口隐藏期间触发的提醒会挂起，在下一次窗口获得焦点时打开任务查看器定位到该任务。

### 2.6 标签与优先级

- 标签可自定义名称与颜色，全局共享（跨项目、跨命名空间），任务可挂多个标签。
- 优先级四级（高 / 中 / 低 / 无），用于排序与筛选；文案只有一处定义，任务编辑器、快捷添加窗与 `!高` 标记共用。
- 新建命名空间 / 项目 / 标签时若未指定颜色，落库一个调色板中的随机色；显式选择「无颜色」则保持无色。新建弹窗在创建模式下预置同一个随机色，使色板预览与提交值一致。

### 2.7 依赖与完成顺序

- 任务之间可设置前置关系（「B 完成前 A 被阻塞」）；**任务级依赖可跨项目**，**子任务依赖限同一父任务内**。
- 循环依赖被拒绝；同一前置重复添加、删除不存在的依赖都是幂等的。
- 被阻塞的任务/子任务在列表上显示「阻塞中」并给出还差几项；勾选完成时**先确认一次**（软阻塞，不禁止完成），确认后照常完成。取消完成永不检查。
- 完成入口有四个（任务行、详情弹窗、子任务行、把看板卡片拖进完成列），它们收敛在同一道检查门上。
- 前置被软删除时依赖自动解除（被阻塞方立即解锁），恢复前置后依赖随之恢复——不需要补偿写入。
- 依赖与手动排序正交：拖拽重排不改依赖边，添加依赖也不动任何排序键。

### 2.8 时间记录

- 任务上可登记耗时：手动录入（开始时间 + 秒数），或「开始/停止」计时。
- 计时入口有两处：详情弹窗里的时间记录区（含读秒、手动录入与记录列表），以及**任务行右侧的开始/暂停按钮**，不必打开详情就能开关计时。
- 行内按钮的状态来自启动时的一次 `time:running`（全部运行中的记录）：**应用内可以同时有多条计时**，每行只关心自己那一条；空闲时按钮随行 hover 出现，计时中常驻高亮。行内不显示读秒。
- `time:start` 幂等——任务已有运行中的记录时返回该记录而不新建；停止以 `now − started_at` 冻结时长，重复停止返回校验错误。
- 计时中的读秒只在本地信号上每秒推进，不写库。
- 记录归属任务，项目/标签维度的时间分布由关联得出（因此不为每条记录冗余项目/标签列）。

### 2.9 评论

- 任务可追加多条评论，用于记录上下文；评论进入全文搜索范围。

### 2.10 搜索

- 基于 SQLite FTS5 对任务标题、备注、评论做全文搜索。
- 全部查询词 ≥ 3 字符时走 FTS5（每个词包成短语、AND 组合、bm25 排序、片段高亮）；任一词不足 3 字符（常见于双字中文词）时整体回退 LIKE 扫描，按更新时间倒序。
- 任务命中在前、评论命中在后；评论命中携带父任务 id/标题，供跳转定位。

## 3. 项目

项目是任务的容器与更高层级的组织单位。

### 3.1 项目字段与状态

名称、描述、颜色标识、图标、所属命名空间（可空）、状态（进行中 / 已归档）。

**项目没有截止日期**：截止是「要完成的那件事」（任务/子任务）的属性，项目作为容器只汇总进度。

### 3.2 三种项目视图

1. **列表视图**：项目内任务按优先级/截止日期/标签排序的清单，含完成率。
2. **看板视图**：固定三列「待办 / 进行中 / 已完成」，随项目创建，**不提供新增/改名/删除列**；任务在列间拖拽切换状态与排序。
3. **进度视图**：项目头部内嵌的总进度条、完成率、剩余任务数。全部由实时任务切片派生，勾选或拖拽完成在同一 tick 就推动进度条。

### 3.3 看板即视图

看板**不持有任务**，它把项目的任务按状态分到三列：

- 已完成（`completed_at` 非空）的任务进完成列——所以列表里勾选完成、详情弹窗里完成、拖进完成列三条路径结果一致。
- 未完成的任务进 `column_id` 指向的开放列。
- 没有列、或列已不存在（列表视图里新建、历史数据）的进**第一个开放列**；这条兜底**以项目为界**，收件箱任务与别的项目的任务不会出现在这块看板上。
- 在本项目内，任务不会因为「没被拖过」而从看板上消失。取消完成不做写入：任务的 `column_id` 一直留着，于是它自动回到原来那一列。
- 换列有两条路径：拖拽，或卡片上 ⋯ 菜单里的「移到 X」（键盘入口；菜单项把卡片追加到目标列末尾）。两条路径写的是同一件事：改列 + 按「是否完成列」联动完成时间 + 写排序键。拖入完成列即完成、拖出即取消完成，与列表侧勾选完全对齐。
- 看板是**同一批任务的另一种展示**，不是另一处归属；每个顶层任务都出现在三列之一。

### 3.4 项目归档与删除

- **归档**是可逆收纳：项目从导航消失、进入侧边栏「已归档」区，可恢复。归档不级联其下任务。
- **删除**（入口在侧边栏项目行的 ⋯ 菜单）连带该项目**全部任务与看板列**一起软删除，同一事务落地——留下指向已删项目的任务会变成无处归属的孤儿行。删除同样是软删（`deleted_at`），备份文档仍包含全部数据；界面上没有「从删除恢复」入口。若正停留在被删项目的页面上，删除后回到收件箱。

## 4. 命名空间（项目分组）

命名空间是把多个相关项目收在一起的容器。

- **单层**：一个项目至多归属一个命名空间；不归属的项目留在根级。
- 侧边栏按命名空间分组显示项目，分组可折叠；创建入口与项目一致——`命名空间 ＋` 标题行紧接 `项目 ＋` 之下。
- 每个存活命名空间行与项目行的行尾悬停浮出两个动作（R11/R13）：**⋯ 更多**（菜单内依次为「编辑」「归档」「删除」，编辑打开与详情页相同的弹窗免导航改名/换色，删除项红色示警）与**＋ 快捷新建**（R11：命名空间行新建项目并预填该命名空间，项目行新建任务并预填该项目）。动作簇是**贴行右缘的覆盖层**而非占位元素：名称独占整行宽度（窄侧边栏下不再被按钮挤没），悬停时整簇带与行一致的底色干净地盖住名称尾部；**悬停高亮跟随整行**（指针落在名称、按钮或展开箭头上，整行一起亮，不分成两段）；键盘 Tab 聚焦、⋯ 菜单展开期间整簇保持可见；隐藏时不接指针事件，点击与拖放照常落在行上。已归档行不加——其行尾是「恢复」。
- 侧边栏宽度可调（R10）：拖右缘把手左右拉伸（192–448px，越界自动钳制），键盘 ←/→ 每次 16px（Home/End 到边界），双击复位默认 224px；宽度持久化，重启保留。折叠成图标栏不受影响，展开恢复记忆宽度。
- 新建/编辑任务、项目、命名空间的弹窗打开时自动聚焦第一个标题/名称输入框（R12），两种模式一致。
- 新建/编辑任务表单排成两列、按「归属 / 属性 / 时间 / 标签」分节（R14）：父任务与所属项目一行，优先级与复杂度一行，截止时间与重复一行，标题、备注、重复间隔与标签通栏；优先级是**四段分段控件**（高 / 中 / 低 / 无，方向键可换）而不是下拉，一次点击即可选中，当前值始终可见。
- 命名空间页展示该组项目列表与汇总进度（项目数、任务完成率，**只数顶层任务**）。
- 新建/编辑项目时可直接在弹窗的命名空间下拉里选「＋ 新建命名空间…」，就地起名，先建命名空间再把项目归入它（一次提交；命名空间那步失败则不建项目）。
- 命名空间可归档与恢复，也可删除（行 ⋯ 菜单）；**归档只影响导航与分组**，不改变其下项目的状态；**删除也只删命名空间自身**（软删），其项目保留归属字段、按存活集合规则回落根级显示（§4.1）。归档项目不进命名空间页（在侧边栏「已归档」区管理）；项目可从命名空间移出（回到根级）。

### 4.1 侧边栏归属规则

- 判定归属用的是**存活命名空间集合**，而不是 `namespaceId` 是否为空：命名空间被软删/不存在时，其项目回落为「未归属」显示在根级，而不是从导航里消失；**归档**命名空间仍算存活——它的项目缩进显示在侧边栏「已归档」区。
- 每个项目只出现在一处：分组行 / 根级平铺 / 已归档平铺 / 已归档分组，四者互斥。
- **侧边栏是一棵可展开的树**：命名空间行展开出项目，项目行展开出该项目**顶层未完成**任务（子任务不单列，完成的任务也不列；默认收起，点击任务行打开任务详情）。展开状态是视图状态，不落库。

### 4.2 拖放调整归属

- 把侧边栏的项目行拖到某个命名空间行上 → 归入该命名空间；拖到根级项目区（含空态）上 → 移出命名空间。
- 任务行有两个落点：
  - 拖到**另一条任务行**上 → 成为它的子任务。只允许一层：落点是子任务、或被拖的任务自己带着子任务时，落点不高亮、松手无变化。
  - 拖到**侧边栏的某个项目行**上 → 移进那个项目，并且**脱离原来的父任务**（界面上会说明这一点）。
- 任务行只在列表视图内可拖；看板卡片仍只服务列间移动。
- 拖拽用原生 Drag API，不引入拖拽库；鼠标按下即可拖，触摸端沿用平台自身的长按起步。
- **每一步拖拽都有键盘等价入口**（拖拽本身只有指针能做）：项目归入命名空间 = 项目编辑器里的「命名空间」；任务认父 / 换项目 = 任务编辑器里的「父任务」/「所属项目」；看板换列 = 卡片 ⋯ 菜单的「移到 X」。

## 5. 统计

统计是**只读的洞察层**，不阻塞核心任务/项目流程。

| 视图 | 内容 |
| --- | --- |
| 完成趋势 | 每日/每周完成任务数折线 + 日历热力图；范围可切「近 7 天 / 30 天 / 本年」 |
| 项目进度 | 各项目完成率、剩余任务量，项目间对比 |
| 时间分布 | 按项目 / 标签聚合的时间花费；粒度可切日 / 周 / 月 |

**计数口径**：完成趋势与项目进度**只数顶层任务**——子任务是父任务内部的一份拆解，不是第二次完成，也不该把进度算成两行。时间分布不受影响：记录在子任务上的时间同样是时间。

「日/周/月」是用户日历上的日/周/月（周桶取该周周一），由前端按用户时区算出的 UTC 半开区间 + 时区偏移参与分桶；无数据的桶由前端补齐坐标轴。图表全部自绘 SVG，不引图表库。

## 6. 桌面能力

| 能力 | 行为 |
| --- | --- |
| 全局快捷键捕获 | 任意界面按下全局快捷键只弹出「快速添加任务」小窗，**不**唤起主界面；录入后消失，不影响当前工作 |
| 快捷输入标记 | 输入框内可用 `@项目` / `!高!中!低` / `#日期` 一次设好所属项目、优先级、截止日期，也可用下方控件设置，控件优先于标记 |
| 系统托盘常驻 | 关闭主窗口后驻留托盘；左键单击切换主窗口显示/隐藏（Linux 上左键直接弹菜单，见 §6.4），菜单为「显示主窗口 / 隐藏主窗口 / 退出 Ordo」 |
| 单实例 | 再次启动（图标、快捷键、命令行）不会开出第二个进程：已有窗口被叫到前台。托盘应用驻留期间这是常态操作 |
| macOS 重新激活 | 窗口留在托盘时点 Dock 图标（或 `open -a`）把主窗口叫回来 |

| 悬浮快速入口 | **未实现**（范围外，见 §8） |

### 6.1 全局快捷键

- 注册**一个**应用级快捷键：macOS 为 `⌘⇧Space`，其他平台为 `Ctrl+Shift+Space`；注册在 Rust 侧而非 webview，因此窗口藏在托盘、最小化或从未聚焦时都能触发。快捷键被其他应用占用时只记日志，不影响启动。Linux 上全局快捷键走 X11，**Wayland 会话下可能注册不上**（同样只记日志，其余功能不受影响）。
- 弹出的是一个 560×150、无边框、置顶、不进任务栏的独立窗口，内容是一行输入 + 一行控件（项目 / 优先级 / 截止日期）+ 一行预览。窗口在启动阶段建好并长期隐藏，所以按下即出、没有 webview 冷启动。
- 回车提交后窗口收回（录入即隐），Esc 同样只隐藏，点击别处也隐藏。每次唤起都从干净状态开始，并重拉一次项目列表。

### 6.2 快捷输入语法

三个标记**都是显式的**，从标题里剥离后提交：`@项目`、`!高/!中/!低`、`#日期`（认全角 `＠`／`！`／`＃`）。

- `#` 后接中文日期短语（今天/明天/后天、周X/下周X/星期X、N天后/N周后、月底/月初/月中 与 3月底、年底/今年底/明年底/2028年底、周末/下周末）或数字写法（`9/30`、`9-30`、`2026-09-30`、`2026/9/30`），都可带 上午/下午/晚上 + N点(半)。
- **日期必须带 `#`**：裸的「明天」「月底」只是标题里的普通文字，所以「月底前完成报表」不会被静默改写成「前完成报表」。
- 多个 `#` 从左往右逐个尝试，第一个能解析成日期的生效；读不出来的留在标题里，且不会挡住后面的 `#明天`。
- 两条贯穿始终的原则是**不猜**和**只删看得懂的**：歧义（`@W` 同时匹配 Work 与 Writing）、匹配不上（`@张三`）、不存在的日期（`2月31日`、`13/1`、`13月底`）一律原样留在标题里。
- 项目名匹配取「token 的最长项目名前缀」（`@Work#明天` 不需要空格也能断开）。只给日期不给时刻时按当天 23:59:59 处理。
- 边界时间词（月底、周末、年底这一族）共用一条周期词规则：`下下/下个/下` 表示往后 1~2 个周期，`本/这/这个` 与光秃形式表示当前周期；不带前缀且已经过去时自动顺延。`#周末` 取周日。
- 控件与标记冲突时**控件优先**（用户最后一次显式点击意图最明确），预览行显示的始终是最终结果。

### 6.4 三端差异与运行前提

同一份代码在三端的行为差异与各自的运行前提（托盘手势、快捷键底层、通知投递、自启写法、数据目录、打包产物、webview 版本下限）逐项列在 [ARCHITECTURE](./ARCHITECTURE.md)§6.3。用户视角最需要注意的四条：

- **托盘左键**：Windows / macOS 切换主窗口显示隐藏；Linux 上左键直接弹出菜单（appindicator 的行为），显示/隐藏/退出都在菜单里。
- **通知**：Windows 需要**已安装**（有注册的应用标识），免安装的裸二进制可能不显示；macOS 需要打包成 `.app` 并由用户授权；Linux 需要系统通知守护进程。
- **快速添加快捷键**：macOS `⌘⇧Space`，Windows/Linux `Ctrl+Shift+Space`；Linux 的 Wayland 会话下可能注册不上。
- **系统要求**：前端产物用到 `oklch()` / `color-mix()` / `@property`（Tailwind v4 的产物），因此 macOS 需要 macOS 13.3 一级的 webview、Linux 需要 WebKitGTK 2.42+；旧 webview 上的表现是样式走样，不是功能报错。

## 7. 设置与数据

- **设置页**：主题（深/浅/跟随系统）、开机自启开关、备份导出与导入。
- **主题**：深浅可切换、可跟随系统；界面只引用设计 Token，不写死色值。
- **备份**：导出把整库写成一个 JSON 文档；导入读取同一文档并**整体替换**全部用户数据。导入前的文件解析/版本校验在事务内完成，外来/更高版本/解析失败的文件不会改动任何数据；恢复前必须经确认弹窗，成功后无需重启即可看到恢复后的数据。
- **隐私**：所有数据仅存本地，不上传任何网络。

## 8. 非功能目标

下表是**目标值**。体积与命令往返已达标并有实测记录（Windows，含口径与验收数据集）；启动耗时只达标一半——冷启动视 WebView2 运行时缓存 0.86–1.6 s，热启动 0.73–0.84 s。数字、口径与缺口见 [ARCHITECTURE](./ARCHITECTURE.md)§6.1 与 [DECISIONS](./DECISIONS.md)§4；动效与无障碍已复查（结论与验证方式见 [ARCHITECTURE](./ARCHITECTURE.md)§6.2，剩余缺口见 [DECISIONS](./DECISIONS.md)§4.2）；三端兼容做了静态核对并在 Windows 上实测（差异、前提与真机清单见 [ARCHITECTURE](./ARCHITECTURE.md)§6.3），**macOS / Linux 仍需真机过一遍清单**。

| 维度 | 目标 |
| --- | --- |
| UI | 统一设计系统（Tailwind v4 `@theme` Token）；Kobalte 无样式原语自建组件，避免第三方 UI 库的「模板感」；一套灰 + 一个强调色；平面四层分层；排版按桌面密度；深色/浅色主题 |
| 运行流畅 | 主界面交互 60fps，长列表虚拟滚动；数据读写走 Rust 后端命令，前端不阻塞主线程 |
| 动效 | 仅用 CSS `transform` / `opacity` / 独立 `scale`·`translate`（唯一例外：侧边栏折叠动画的 `width`）；微交互 150–300ms；遵循「减少动态效果」；不做退场动画 |
| 体积 | Windows 安装包 < 30 MB（压缩后 < 15 MB），macOS / Linux 同量级 |
| 响应 | 冷启动（首屏可交互）< 1.5s，热启动 < 0.5s；任务/项目操作命令往返 < 50ms；统计查询秒级返回 |
| 平台 | Windows / macOS / Linux 三端一致体验；全局快捷键与托盘按平台适配；差异清单见 [ARCHITECTURE](./ARCHITECTURE.md)§6.3 |
