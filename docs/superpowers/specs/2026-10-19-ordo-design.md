# ordo — 个人任务账本（桌面应用）设计文档

日期：2026-10-19
状态：待评审（builder check 未回）
参与者：用户（项目负责人）、设计对话

## 1. 这个东西为什么存在

使用者是一个人，作为项目负责人同时跟几个项目，项目以甲方交付为主，内部按专业拆分：**软件、硬件、测试、结构、生产、资料**。每个专业由不同同事负责，他要定期问、定期汇总、随时能对上汇报。

他现在的工具是一本手写笔记本。它赢在快到没有摩擦，输在三件事：

1. **只进不出**：记下来之后没有东西会来追，清单越写越厚，也越来越不可信。
2. **忘了划**：事情往往做完了，但划掉这个动作从来不会发生，于是做过的和没做的长得一样。
3. **不会长大**：记的时候是一句，事后发现得拆成几步，纸上一句永远是一句。

另外，他每周本来就在做一件事：把上周抄下来、还要继续的事项重抄一遍到新的一页。这个动作存在了几十本笔记本，它不是我们要发明的习惯，而是我们要替换掉的动作。

所以 ordo 不是又一个待办清单。它是一个**会追问的账本**：捕获和纸一样快，但它会在每周把上周的东西摆到你面前，逼你逐条结清。

## 2. 成功的样子

- 开完会、被口头交代完，**3 秒内**记下一句，什么归属都不用想。
- 任何程序前面按一个键就唤出迷你窗口，敲一句回车，立刻消失。
- 每周打开时，用一次**约 3 分钟**的"过一遍"，把上周抄下来的每一条都结掉：继续 / 完成 / 算了 / 拆开。
- 打开任何项目，一眼看到各专业走到哪、谁拖着，并能复制一句"总结"直接发企微或口头说。
- 做完了不用记得去划掉——勾完最后一步，它自己变成已完成。
- 有截止日的事，在前一天 17:30 被系统通知叫住，哪怕窗口是关着的。

## 3. 目标 / 非目标 / 反目标

### Phase 1 目标

- 顶部常驻捕获条，一句话回车即存，零必填。
- 任务：可选归属项目、一个分类、多个标签、一个负责人、可选开始/截止日期、三态（未开始 / 进行中 / 已完成）。
- 任务可拆成**有序步骤**；第一步即"当前阶段"。
- **本周工作集**：显式圈定的清单，不是"所有没做完的事"。
- 每周"过一遍"卡片流，四个出口。
- 项目页：按分类折叠的进度视图 + 时间轴视图（类甘特）+ 可复制的总结句。
- 简单统计：每周完成量、分类分布。图表不做花哨交互。
- 截止日前一天 17:30 的系统通知；应用常驻托盘、开机自启（可关）；错过补报。
- 任务和项目都能归档；归档页可搜索。
- 本地数据 + 自动备份 + 手动导出 JSON。
- AI 补字段：一句话捕获后，后台把项目 / 分类 / 负责人 / 日期 / 标签自动填好，可关、可改、不挡保存。
- 延期原因：改期或逾期时顺手记下"为什么延"，成为项目滞后的证据。

### Phase 1 明确不做

- 任务之间的依赖关系、关键路径、自动排期。时间轴只按开始/截止画条，不画连线。
- 每日打卡、看板、习惯、连续天数。
- 移动端应用（只在架构上留位置）。
- 云端、账号、共享链接、多人编辑、权限。
- 富文本、附件、子任务的子任务（步骤只有一层）。
- 团队协作：同事不登录、不安装。
- 聊天式 AI 助手／对话式规划。AI 只做补字段和可选建议，不做聊天窗口。

### 反目标（做出来也算失败）

- 需要用户养成新习惯才成立的设计。
- 任何在捕获时要求先选分类/项目/时间的交互。
- 需要用户额外维护才能保持准确的统计。
- 任何一步比掏笔和本子更慢。

## 4. 约束与前提

- 桌面应用，Windows 优先（用户当前环境），Tauri 2。
- 仓库已有脚手架：Tauri 2 + Vue 3 + Vite+（`vp`）+ Tailwind 4 + daisyUI 5，`ordo`。
- 单机、本地存储、无服务器、无账号。
- 单人使用（"我"）；同事只是记录里的名字，不是用户。

## 5. 核心模型

所有实体都带 `id`（UUID）、`created_at`、`updated_at`；删除用软删除（`deleted_at`）。理由见 §11。

**Person（人）**

- 名字、"我"标记、颜色。
- "我"也是其中一行，不写死在界面里。
- 全局只有一份人名表；**每个项目有自己的成员列表**（人 ↔ 项目多对多）。加成员时可以选已有的人，也可以直接造一个新人。
- "我"自动属于每个项目，不可移除。
- **负责人候选**：任务属于项目时，只能选该项目的成员；任务不属于任何项目时，从全局人名表里选（默认"我"）。
- 人名全局唯一，改名全局生效。没有独立的人员管理页：成员关系在项目设置里管；只有没有任何任务引用的名字才允许彻底删除。
- 用来做负责人，将来可升级成账号。

**Project（项目）**

- 名称、可选截止日、状态（进行中 / 已归档）。
- 成员列表（含固定的"我"）。
- 项目设置里管理：名称、截止、成员、归档、删除。

**Category（分类）** = 任务的归属，单选，值很少：

- 默认：软件、硬件、测试、结构、生产、资料、杂事、非项目。
- 可增删改，顺序可调。
- 分类同时承担"这个项目里各专业的进度"这一维度——项目里**不再单独建模块层**。

**Tag（标签）** = 任务的性质，多选，自由输入：`fix`、`feat`、`甲方催` 之类。

**Task（任务）**

- 标题（就是捕获时那句话，永远保留原句）
- 项目（可选）、分类（可选，默认空）、标签（可多）、负责人（可选，默认"我"）
- 开始日期（可选）、截止日期（可选）
- 状态：未开始 / 进行中 / 已完成
- 是否在本周工作集、被"继续"过几次（`carry_count`）
- 是否归档
- 挂起：**预期开始日期（挂起时必填）**；挂起期间不在本周集，但仍属项目范围内
- 取消：归档并标记取消，**不再计入项目的任何进度数字**
- 备注（纯文本）

（Phase 1 不做手动排序；本周集按截止日排，无截止的按加入顺序。评审后定。）

**Delay（延期记录）**

- 所属任务、原截止日、新截止日、原因（可选）、时间。
- 每次改期或逾期记一条，见 §5.1。

**Step（步骤 / 阶段）**

- 所属任务、标题、顺序、是否完成、可选日期。
- 只有一层，不再嵌套。
- 步骤有序 = 表达"先设计再实现"；跨分类（软件 vs 硬件）天然并行，不需要任何依赖机制。

### 状态规则

- 没有步骤的任务：手动切换三态。
- 有步骤的任务：由步骤推导——全部完成→已完成；有任一完成→进行中；否则未开始。推导状态下不提供手动改状态。
- 勾完最后一个步骤自动变已完成，这是对"忘了划"的解法。

### 5.1 延期与延期原因

- 把截止日往后改时，问一句"为什么延？"（可跳过），记一条延期记录：原截止 → 新截止、原因、时间。
- 截止日已过仍未完成：任务行显示"逾期 N 天"，旁边一个"记原因"入口，只提示、不阻塞。
- 原因在任务浮层里按时间列出，最近一条显示在任务行上。
- 项目页显示"延期 N 项"，但默认不写进总结句——总结是给外人看的，延期原因是你自己看的。
- 延期记录不改变任务状态，只解释它为什么慢。

### 归档规则

- 项目归档：从项目列表移入归档页，任务全部保留可查。
- 任务归档：从本周集、项目视图移出，归档页可搜。
- **取消**的任务直接归档，并从项目中消失：不进分母、不进总结句、不提醒。它等于从范围里划掉。
- **挂起**不是归档：它还在项目里，只是暂时不在本周集；到预期开始日期会被叫醒。

## 6. 本周工作集与"过一遍"

**本周工作集是一个显式集合，不是查询结果。**

- 新捕获的任务默认进入本周集。
- 有截止日的任务，在其截止日所在周自动进入本周集（否则提醒了却不在眼前）。
- 从"挂起"里手动捞回来、或挂起到期后选择开始时重新进入。
- **集合里没有任何东西会自己消失。** 一件任务只有经过"过一遍"的某个出口（继续 / 完成 / 挂起 / 取消）或随项目归档，才会离开。几周不打开也不会丢东西。
- 注意：取消是唯一的"消失"方式，且它同时意味着任务从项目范围里划掉。挂起只是推迟。

**"过一遍"**（每周一次，进入新的一周的第一次打开时触发；可稍后，但不能永久跳过而不留痕）：

- 全屏卡片流，一次一张，一次只看一件事。
- 每张卡片显示：标题、项目、分类、负责人、截止、"第 N 次抄回来"。
- 出口（"拆开"是动作，不是结局）：
  - **继续** → 留在本周集，`carry_count + 1`。
  - **完成** → 已完成。
  - **挂起** → 移出本周集，**必须选一个预期开始日期**；到期那天会被提醒"该开始了"。
  - **取消** → 直接归档，从项目范围和所有统计里划掉。
  - **拆开** → 打开右侧浮层拆成步骤，拆完仍需选一个出口。
- `carry_count >= 3` 时在卡片上给出温和提示："连续 N 周没动，要不要拆开或挂起？"
- 过完之后给一句小结：本周 X 件在推进，结掉 Y 件，挂起 Z 件，取消 W 件。

几条配套规则（评审后补）：

- **过一遍列的是当下集合里的全部事项**，包括前几天刚记的。"继续"是让它留下的唯一动作。
- 如果几周没打开，下一次过一遍一次列全，不按周切分，也不丢东西。
- `carry_count` 计的是"你确认继续过几次"，不是自然周数；跳过两周再继续只 +1。
- 逾期未结的事仍留在集合里，会继续出现在每一轮过一遍中。
- 集合只在"过一遍"里变小；它不会被时间自动清理，这正是它与纸的区别。

## 7. 界面

两个窗口：主窗口（三个页面 + 若干覆盖层）与迷你窗口。

1. **本周**（默认落地页）
   - 顶部常驻捕获条："记一句…（回车保存）"。
   - 下方是本周工作集列表，按截止日排序，无截止的按加入顺序。
   - 有新一周时，顶部出现一条"上周 12 件待定 → 过一遍"的入口。
   - 每一行：标题、分类、负责人、截止（逾期标红）、步骤进度。
   - 底部一个可折叠的**"挂起 (N)"**区：列出挂起的任务和各自的预期开始日期，点一下可以提前捞回本周集（`carry_count` 不变）。

2. **项目**
   - 项目列表 → 单个项目页；列表底部有"新建项目"。
   - 项目页顶部：名称、截止、剩几天、总进度条（X/Y 完成），以及"⋯"进入项目设置（名称、截止、成员、归档、删除）。
   - 项目页顶部同样有一条捕获条，在那里记的任务直接归属该项目。
   - 默认视图：**按分类折叠**。四条（或更多）分类行各带进度条，点开看到该分类下的任务、负责人、截止。
   - 第二视图：**时间轴**（见 §8）。
   - 底部一行自动拼好的**总结**，一键复制：
     > 华东客户交付 11/20 截止，16 项完成 6；软件 3/7，硬件 1/4，结构 2/2，资料未动。

3. **归档**
   - 项目归档列表 + 任务归档列表 + 已取消列表，带搜索框。
   - **可恢复**：放回原处。
   - **可删除**：永久删除（连同步骤和延期记录），弹确认，不可撤销。恢复与删除两个按钮拉开距离，防手滑。

4. **过一遍** 覆盖层：全屏卡片流，见 §6。

5. **任务浮层**（右侧）：标题、**项目**、步骤列表（回车加一步）、状态推导提示、分类/负责人/标签/日期/备注。拆开也在这里发生。
   - 捕获时不问项目；归属在浮层里选（或就地新建项目）。项目页里直接新建的任务自动带上该项目。
   - 负责人：有项目时只能从项目成员里选；无项目时从全局人名表里选。把任务挪进另一个项目时，若负责人不是该项目成员，自动把他加进成员列表（并在浮层里说一句）。

6. **设置**（浮层，从顶栏齿轮或托盘菜单打开）：AI（DeepSeek）、**全局快捷键**、开机自启、备份保留天数、周起点、**分类与标签的增删和排序**、导出 / 导入 JSON。
   - 人员**不在**设置里，而在各项目的项目设置里。
   - 标签可在这里增删；在任务里输入一个新标签也会自动收进列表。删标签只影响显示，已打过的任务不变。

7. **迷你窗口**（全局快捷键唤出，独立于主窗口）
   - 无边框、置顶、不进任务栏，约 560×96，屏幕中上方。
   - 只有一个输入框、一行提示（`⏎ 保存 · Esc 关闭`）和一个打开主窗口的小按钮。
   - 回车立即落库并显示 0.8 秒“已记下”，随后自己藏起来；不等 AI 补字段，AI 结果直接在主窗口里出现。
   - 默认快捷键 `Ctrl+Alt+O`，设置里可改；改了不生效会退回原来的键并告诉你。

**交互底色**：键盘优先。捕获条 `Enter` 保存并继续。过一遍用方向键/单键操作。

## 8. 时间轴（"甘特"，不画依赖）

- 每个项目一页，横轴为日期，可切换 4 周 / 8 周 / 自定义范围。
- 每个任务一行，按分类分组（可折叠）。
- 条形 = 开始 → 截止。
  - 只有截止没有开始：从范围起点（或创建日）画到截止，左端虚线表示"开始未定"。
  - 只有开始没有截止：右端虚线延伸到范围末尾。
- 只有截止日的任务才会被提醒；时间轴上的虚线只是诚实表示"这里不确定"。
- **只读**：Phase 1 不支持拖动改期。改期在任务浮层里。
- 不画依赖连线、不算关键路径。

## 9. 统计

- 项目：总完成度、各分类完成度（项目页自带，无需另开）。
- 每周：这周完成多少、新记多少、放弃多少。
- 分类：各分类未完成 / 已完成的数量分布。
- **分母规则**：取消的任务不进任何分母与总数；挂起的任务仍在分母里（它还在范围内，只是推迟）。
- 只做读得懂的图，不做趋势预测、不做排行榜。
- 不做独立统计页：每周三条数字做成"本周"页底部的小面板，分类分布跟着项目页走。

## 10. 提醒与托盘

- 只有带截止日、未完成、未归档的任务触发。
- 触发时间：**截止日前一天 17:30**。
- 方式：系统通知（Windows 通知中心），点击打开应用并定位到该任务。
- 应用常驻托盘；关闭窗口 = 最小化到托盘，不退出（退出在托盘菜单里）。
- 开机自启默认开，可在设置里关。
- 应用没运行 / 机器关着而错过：下次打开时汇总显示"你错过了这几条"。
- 托盘图标在有未读提醒时给角标或一次闪烁。
- 已完成 / 已归档的任务不再提醒。
- 去重：同一任务对同一个截止日只提醒一次，应用重启不会重复弹。
- 逾期仍未完成：逾期当天 17:30（或之后第一次启动时）再提醒一次，措辞为"已逾期"，仅一次。
- 托盘角标 = 自上次打开"本周"以来未读的提醒数。
- 补报只覆盖最近 14 天，更早的不再打扰。

**挂起到期提醒**（用户要求）：

- 挂起的任务在**预期开始日期当天 09:00** 提醒一次："该开始了——<任务名>"。
- 通知里给两个动作：**开始** / **再等等**。
  - 开始 → 回到本周集，状态转为进行中。
  - 再等等 → 必须另选一个预期开始日期（日期是挂起的必填项）。
- 没打开应用而错过：下次启动时补报，措辞为"有几件事该开始了"。

## 11. 为将来留的口子（不是现在就做云端）

用户明确：云端和同事一起用是**以后可能**的事。以下几条是现在做很便宜、以后补很贵的预防针：

- 所有实体用 UUID，不用自增整数。
- 每行都有 `created_at` / `updated_at`，删除是软删除。
- 人是一等实体，任务只存 `person_id`；"我"只是一行数据。
- 数据访问集中在 repository 层，界面不直接碰存储。
- 本周集合是显式布尔值，不是按日期算出来的。
- 界面逻辑与数据逻辑分层，将来 Vue 界面可复用到移动端。

**不做的**：同步协议、冲突解决、事件日志、CRDT、任何联网代码。这些是 Phase 3 的事，届时需要单独设计。

## 12. AI 辅助（默认开，可关）

**原则**：AI 永远不挡在保存前面。捕获是一瞬间的事，AI 是事后补字段。这也适用于全局快捷键唤出的那一句。

**流程**

1. 回车 → 原句立刻存进本周集，界面不等任何网络。
2. 后台把「原句 + 现有项目名 / 分类名 / 人名」发给模型，要求返回结构化字段：项目、分类、负责人、开始、截止、标签；一句话里有多件事时可以返回多条。
3. 返回后，这条任务下面浮出一排可点的字段标签（`软件` / `老李` / `截止 周五`）；点掉即删除，点开即改。
4. 拿不准的字段留空，宁可空着也不瞎猜。用户手动改过的字段，AI 永远不覆盖。
5. 一句话里检测到多件事时，AI 只能**提议**拆成 2–3 条，要点"接受"才生效。

**接入方式（Phase 1 只认 DeepSeek）**

- DeepSeek 官方 API，OpenAI 兼容格式：base URL `https://api.deepseek.com`，默认模型 **`deepseek-flash`**（设置里可切 `deepseek-v4-pro`）。
- 结构化输出用 JSON Output：`response_format: { "type": "json_object" }`。官方有两条硬要求——system prompt 里必须出现 "json" 字样并给出输出样例；`max_tokens` 要留够防止截断。
- **用非思考模式**（`thinking: { "type": "disabled" }`），一次补字段应在 1–2 秒内回来。思考模式默认是开的，必须显式关掉，否则慢且贵。
- 官方文档承认 JSON Output 有概率返回空 content：按失败处理，最多重试一次，然后静默放弃。
- 设置里保留 base URL / 模型名 / key 三项可改，将来换通义或 Ollama 只改这三行；但 Phase 1 只保证 DeepSeek 这条路是通的。
- 不填 key → 完全退化成纯本地一句话捕获，其余功能不受影响。
- key 存本机（系统凭据库或本地配置，由实现计划定），不进导出文件、不进备份。

**隐私**：只有 AI 开着才联网；发出去的是那一句话 + 你现有的项目/分类/人名列表，不发历史任务。任务里若写了客户敏感信息，这些字会到 DeepSeek 的服务器；介意就在设置里整体关掉。

**失败**：超时、断网、返回不合法 → 静默放弃，任务保持为仅一句话，不弹错、不打断。

**同一接口将来可复用（Phase 1 不做）**：拆开时建议步骤、总结句润色、按项目生成周报。

## 13. 数据与安全

- 本机单库存储（SQLite 或单文件 JSON 由实现计划决定），写入必须原子。
- 自动备份：每日一份副本，保留若干天。
- 手动导出 / 导入 JSON。
- 无遥测。唯一的联网行为是 AI 补字段，且可在设置里整体关闭（关掉后完全离线）。
