## 1. Ordo 是什么

Ordo 是一款 **local-first、单用户**的桌面应用，核心能力是**个人任务管理**与**项目管理**，附带**只读的统计展示**。数据全部落在本机 SQLite，不需要账号与网络即可完整使用。

- **技术形态**：Tauri 2（Rust 后端 + 系统 WebView）+ SolidJS/TypeScript 前端，Windows / macOS / Linux 三端同一份代码。
- **交互形态**：前端持有全量数据、写操作走乐观更新的单页应用；关闭主窗口驻留系统托盘，全局快捷键唤起独立的快速添加小窗。
- **数据形态**：SQLite 单文件，UUID 主键 + ISO-8601 UTC 时间戳 + 软删除；迁移由 refinery 内嵌 SQL 管理。

## 3. 术语表

文档与代码注释共用这套词，含义以本表为准：

| 术语 | 含义 |
| --- | --- |
| **任务（Task）** | 最小管理单元，一条 `tasks` 行。可归属项目，也可无归属（即收件箱任务） |
| **子任务（子行）** | 有父任务的任务，即 `parent_task_id` 非空的行。**它就是一条普通任务行**，不是独立实体；层级只有一层 |
| **父任务** | 有子任务的任务行 |
| **命名空间（Namespace）** | 把多个相关项目收在一起的容器，单层；一个项目至多归属一个 |
| **收件箱** | `project_id` 为空的顶层任务所在的视图 |
| **依赖边 / 前置** | `task_dependencies` 的一行 `(task_id, depends_on)`，读作「task 等待 depends_on」 |
| **阻塞（软阻塞）** | 存在未完成前置时的状态。它是前端派生量，只用一次确认拦一下，**不禁止**完成 |
| **看板泳道** | 项目固定三列（待办 / 进行中 / 已完成）中的一列。看板是同一批任务的另一种展示，不是第二处归属 |
| **归档** | 项目/命名空间的「软删除」，可从归档区恢复；归档不级联其下内容 |
| **软删除** | 写 `deleted_at` 而非 `DELETE`。查询默认过滤 `deleted_at IS NULL` |
| **字典序键（fractional indexing）** | `sort_order` / `position` 用的 TEXT 排序键，可在任意两键之间插入中间键而无需重排已有行 |
| **编号** | 文档与代码注释里 `R7c`、`V7`、`D-02`、`ST-01`、`F-08` 这类简写，定义见 [DECISIONS.md](./DECISIONS.md) |

## 5. 维护规则

1. **代码是事实来源。** 任何一条声明都应能在代码里找到对应位置；发现不一致时先改代码或先改文档，不要让两者分叉。
2. **改行为 → 同时改文档。** 行为/范围变化更新 `PRODUCT.md`；结构、模块边界、命令面、设计系统变化更新 `ARCHITECTURE.md`；数据模型、迁移、备份、统计口径变化更新 `DATA.md`；新增决策或新增编号更新 `DECISIONS.md`。
3. **不写计划。** 本文档集描述现状，不描述"打算做什么"。待办与缺口集中记在 `DECISIONS.md` 的未完成项一节，做完即改写为现状描述。**唯一例外是 [AI.md](./AI.md)**：它是经确认的规格（内容尚未实现）。实现落地时同样按上一条把结论回写进 PRODUCT / ARCHITECTURE / DATA / DECISIONS，`AI.md` 只保留「为什么这样设计」与未完成项。
4. **不写施工台账。** 里程碑任务表、逐次变更记录、实施计划不进本文档集——它们属于提交历史。
